Phase 4 — Retire libwayland-server

Remove the mature server dependency only after the Wayring path is canonical and rollback risk is closed.

Tentative

Standing constraints

  • Wayring stays reusable, policy-free, scanner-generated, and sans-I/O; Keywork owns event-loop, scene, render, and shell policy.
  • No fake libwayland surfaces, Scene frontend unions, duplicate identity domains, or mature protocol-object migration.
  • Core protocol contracts come from the official Wayland 1.26.0 XML pinned by build.zig.zon and scanner-generated by the root build.
  • Debug validation only: formatting, aggregate tests, renderer checks, Wayring tests, Oracle review, then an independent gate.
  • Wayring client support and removal of libwayland-client are a separate track.
